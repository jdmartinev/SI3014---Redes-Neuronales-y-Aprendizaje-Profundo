# Deep Learning Project

## 📅 Timeline

### Phase 1: Proposal
**Due:** May 8  

Teams must submit a proposal including a clear plan for **modeling, training, and validation**.

---

## 1. Problem Definition
- What problem are you solving?
- Why is it relevant?
- Task type:
  - Image Classification / NLP / Time Series / Audio / etc.

---

## 2. Dataset
- Source of the dataset
- Description:
  - Inputs (X)
  - Labels (y)
- Dataset size
- Data modality:
  - Images / Text / Tabular / Audio / etc.

---

## 3. Data Splitting Strategy ⚠️ (Mandatory)
Clearly define:
- Training set (%)
- Validation set (%)
- Test set (%)

Explain:
- Why this split makes sense
- Whether stratification is used (if applicable)

---

## 4. Data Preprocessing
- Cleaning steps
- Normalization / standardization
- Tokenization (if NLP)
- Resizing / augmentation (if CV)

---

## 5. Model Architecture (Planned)
- Model type:
  - CNN / RNN / Transformer / MLP / Hybrid
- Key components:
  - Layers
  - Activations
  - Embeddings (if applicable)

> You may use pretrained models (transfer learning), but justify it.

---

## 6. Training Strategy (Planned)
Define:
- Loss function
- Optimizer
- Learning rate
- Batch size
- Number of epochs

Optional but recommended:
- Learning rate scheduler
- Regularization:
  - Dropout
  - Weight decay

---

## 7. Validation Strategy ⚠️ (Mandatory)
- How will you monitor performance?
- Metrics:
  - Accuracy, F1, BLEU, etc.
- Early stopping? (yes/no)
- Model selection criterion:
  - Best validation loss?
  - Best metric?

---

## 8. Initial EDA
- Data distribution
- Class imbalance
- Examples of samples
- Include at least **1–2 plots or visualizations**

---

## 9. Research Question & Objective

**Question:**
- Clear and specific

**Objective:**
- What your model should achieve

---

## 10. References
- Minimum 2–3 sources (papers, blogs, documentation)

# Phase 2: Final Project
**Due:** May 28 – 11:59 PM  

Teams must **train, validate, evaluate, and analyze** a deep learning model.

---

# 📄 Deliverables

---

## 1. Project Report (Max. 2 pages, PDF)

### Problem Statement
Brief description of the task, dataset, and objective.

---

### Model Architecture
- Final architecture used
- Key design decisions
- Pretrained vs from scratch

---

### Training Procedure ⚠️ (Critical Section)
Include:
- Loss function
- Optimizer
- Learning rate
- Batch size
- Number of epochs
- Hardware used (GPU/CPU)

Also include:
- Training curves (loss/metric vs epochs)

---

### Validation Strategy ⚠️ (Critical Section)
- Validation metrics
- Early stopping (if used)
- Model selection strategy

---

### Results
Include:
- Final test performance
- Comparison: train vs validation vs test
- Overfitting / underfitting analysis

---

### Error Analysis (Highly Recommended)
- Where does the model fail?
- Examples of incorrect predictions

---

## 2. Video Presentation (Max. 10 minutes)

Explain:
- Problem and motivation  
- Model architecture  
- Training process  
- Validation strategy  
- Results and insights  
- Lessons learned  

---

## 3. Code Repository (GitHub or similar)

The repo must contain:

- A clear `README.md` with instructions on how to run the code  
- Training and evaluation code  
- Any pretrained models or checkpoints (if applicable)  
- `requirements.txt` or `environment.yml` for dependencies  
- An AI usage statement  

### AI Usage Statement

Students must include a brief statement indicating whether AI tools were used during the development of the project.

If AI tools were used, the statement should describe:

- The AI tools used  
- The purpose of their use  
- Which parts of the project were supported by AI (e.g., coding, debugging, documentation, analysis, experimentation, etc.)

Students are fully responsible for understanding, validating, and explaining all submitted work.
